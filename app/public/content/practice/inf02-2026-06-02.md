# INF.02-02-26.06-SG: патч-панель T568B, VLAN 3, FTP-сервер IIS и Linux-станция с FileZilla

Сценарий: монтируешь линию патч-панель ↔ розетка Keystone, определяешь параметры станции в Linux, настраиваешь роутер (WAN статический, LAN, DHCP с резервацией) и коммутатор (VLAN 3). На Windows Server — интерфейсы, имя, принтер, сайт FTP в IIS; на Linux-станции — сеть, группа и пользователь из терминала и подключение FileZilla к FTP. Оценивается 5 результатов: кабели и подключение, идентификация, сетевые устройства, сервер, станция + ход монтажа.

## Порядок работы (план на 150 минут)
1. Монтаж кабеля и тест при экзаменаторе (0–25 мин).
2. Подключение устройств по схеме (25–30).
3. Роутер: WAN, LAN, DHCP (30–45); резервацию — когда узнаешь MAC сервера.
4. Коммутатор: IP, VLAN 3 (45–55).
5. Сервер: интерфейсы, имя (перезагрузка), принтер, файл и печать (55–80).
6. IIS + FTP (80–100).
7. Linux: идентификация, сеть, пользователи, FileZilla (100–130).
8. Проверка связи с экзаменатором, резерв (130–150).

## Задание 1. Монтаж кабельной линии
**Что требуется**
- Кабель U/UTP: один конец в любое гнездо патч-панели по **T568B**, другой — в модуль Keystone настенной розетки по **T568B**.
- Кабель типа «drut» (одножильный, solid), розетка с одним модулем Keystone собрана, патч-панель закреплена в стойке RACK.

**Как сделать**
1. Порядок T568B: бело-оранжевый, оранжевый, бело-зелёный, синий, бело-синий, зелёный, бело-коричневый, коричневый. Ориентируйся на цветовую маркировку «B» на панели и модуле.
2. Сними оболочку стриппером примерно на 3–4 см, пары раскручивай минимально (≤ 13 мм), проводники за оболочкой ≤ 25 мм.
3. Заделай жилы ударным инструментом (`narzędzie uderzeniowe` 110/LSA), лишнее обрежь.
4. Модуль вставь в лицевую панель розетки, собери розетку полностью.
5. Панель закрепи в стойке винтами, лицом наружу. Подними руку и протестируй линию тестером при экзаменаторе (патч-корды с обеих сторон).

**Как проверить**
- Тестер показывает 1–8 по порядку, без перекрёстов и обрывов.

**За что дают баллы**
- Все жилы по T568B на панели и в Keystone, ≤ 25 мм без оболочки, ≤ 13 мм раскрученных пар; розетка собрана; тест успешен; кабель «drut»; панель стабильно и лицом наружу; все устройства по схеме. Ход работы: инструменты по назначению, BHP, порядок на столе.

**Частые ошибки**
- Взять многожильный (linka) кабель.
- Раскрутить пары слишком сильно.

## Задание 2. Идентификация параметров в Linux
**Что требуется**
- Таблица 3: версия ядра; GPU — производитель и модель; CPU — модель, базовая частота, число ядер.
- Скриншоты в каталог `Identyfikacja` на USB `Egzamin-x`.
- Оценка CPU для эмулятора PS3: Intel или AMD, ≥ 6 ядер, ≥ 3 GHz.

**Как сделать**
```bash
uname -r                                   # версия ядра
lspci | grep -i -E "vga|3d|display"        # производитель и модель GPU
sudo lshw -C display                       # vendor / product подробно
lscpu                                      # Model name, Core(s) per socket, Socket(s)
sudo dmidecode -t processor | grep -i -E "version|speed|core count"
mkdir -p /media/$USER/Egzamin-x/Identyfikacja
```
Скриншоты (`PrtSc`) скопируй в `Identyfikacja`.

**Как проверить**
- Число ядер = `Core(s) per socket × Socket(s)` (не `CPU(s)` — это потоки). Базовая частота обычно в названии модели (`@ 3.20GHz`) или `Current/Max Speed` в dmidecode.

**За что дают баллы**
- Каждый параметр (ядро, производитель GPU, модель GPU, модель CPU, базовая частота, ядра) записан и совпадает со скриншотом; есть оценка по трём требованиям.

**Частые ошибки**
- Записать потоки вместо ядер.
- Записать текущую частоту (`CPU MHz`) вместо базовой.

## Задание 3. Роутер
**Что требуется**
- WAN: `78.80.88.5/29` (маска `255.255.255.248`), шлюз `78.80.88.1`, DNS `8.8.8.8`, `8.8.4.4`.
- LAN: `192.168.100.1/24`.
- DHCP: включён, `192.168.100.20 ÷ 192.168.100.50`, резервация `192.168.100.50` для интерфейса сервера, подключённого к коммутатору (LAN1).

**Как сделать**
1. `Network → WAN`: тип `Static IP`, IP, маска, шлюз, Primary/Secondary DNS — сохранить.
2. `Network → LAN`: `192.168.100.1`, `255.255.255.0`. Перезайди на новый адрес.
3. `DHCP → DHCP Settings`: Enable, Start `192.168.100.20`, End `192.168.100.50`.
4. `DHCP → Address Reservation`: MAC адаптера LAN1 сервера (`ipconfig /all` → «Adres fizyczny»), IP `192.168.100.50`. Подними руку.

**Как проверить**
- После `ipconfig /renew` LAN1 сервера = `192.168.100.50`.

**За что дают баллы**
- LAN 192.168.100.1/24; WAN 78.80.88.5/255.255.255.248, шлюз 78.80.88.1, DNS 8.8.8.8; DHCP с диапазоном; резервация .50.

**Частые ошибки**
- Маска /29 введена как 255.255.255.240.
- Резервация на MAC интерфейса LAN2.

## Задание 4. Коммутатор
**Что требуется**
- IP `192.168.100.10/24`, шлюз `192.168.100.1`.
- 802.1Q включён, VLAN 3 с портами 1, 2, 3 без тегов; на L3 IP на VLAN 3, VLAN 3 — управляющий (если требуется).

**Как сделать**
1. `System → IP Setting`: static, `192.168.100.10`, `255.255.255.0`, шлюз `192.168.100.1`.
2. `VLAN → 802.1Q VLAN`: Enable; создать VLAN 3, порты 1–3 Untagged; убрать их из VLAN 1.
3. `802.1Q PVID Setting`: PVID портов 1–3 = 3.
4. Management VLAN = 3 (если есть такая опция). Подними руку.

**Как проверить**
- `ping 192.168.100.10` со станции.

**За что дают баллы**
- IP/шлюз коммутатора; создан VLAN 3; порты 1–3 untagged.

**Частые ошибки**
- Сменить PVID на 3 без management VLAN 3 — коммутатор перестанет отвечать на свой IP.

## Задание 6. Windows Server
**Что требуется**
- `LAN1` — автоматически (получит `192.168.100.50`), обновить аренду; `LAN2` — `192.168.0.X/24`.
- Имя компьютера `SERWERX` (X — номер стенда).
- Принтер TCP/IP `192.168.0.200`, RAW, драйвер из `DRUKARKA`.
- Папка `C:\MOJE_FTP`, в ней `EGZAMIN_INF02.txt` с номером стенда; распечатать (поднять руку), приложить к листу.
- Роль IIS с FTP; сайт `INF_FTP`, путь `C:\MOJE_FTP`, IP `192.168.100.50`, порт 21, без SSL; анонимные — чтение, Administrator — чтение и запись.

**Как сделать**
1. `ncpa.cpl`: переименуй адаптеры в LAN1/LAN2, настрой IPv4. `ipconfig /renew`.
2. `Menedżer serwera → Serwer lokalny → Nazwa komputera → Zmień` → `SERWERX`, перезагрузка.
3. Принтер: `Urządzenia i drukarki → Dodaj drukarkę → Dodaj drukarkę przy użyciu adresu TCP/IP` → `192.168.0.200`, порт `Niestandardowy` → `Raw`, 9100 → `Z dysku…` (папка DRUKARKA).
4. Создай папку и файл в Notatniku, `Plik → Drukuj`.
5. `Menedżer serwera → Zarządzaj → Dodaj role i funkcje` → `Serwer sieci Web (IIS)` → в `Usługi ról` отметь `Serwer FTP → Usługa FTP` (и `Konsola zarządzania usługami IIS`).
6. `Menedżer internetowych usług informacyjnych (IIS)` → ПКМ `Witryny → Dodaj witrynę FTP`: nazwa `INF_FTP`, ścieżka `C:\MOJE_FTP` → `Powiązanie`: Adres IP `192.168.100.50`, Port 21, SSL: `Bez protokołu SSL` → `Uwierzytelnianie`: Anonimowe + Podstawowe; `Autoryzacja`: Użytkownicy anonimowi — Odczyt.
7. На сайте `Reguły autoryzacji FTP → Dodaj regułę zezwalającą`: `Określeni użytkownicy: Administrator` — Odczyt i Zapis.

```powershell
Rename-NetAdapter -Name "Ethernet" -NewName "LAN1"; Rename-NetAdapter -Name "Ethernet 2" -NewName "LAN2"
New-NetIPAddress -InterfaceAlias "LAN2" -IPAddress 192.168.0.X -PrefixLength 24
ipconfig /renew LAN1
New-Item C:\MOJE_FTP -ItemType Directory; Set-Content C:\MOJE_FTP\EGZAMIN_INF02.txt "X"
Install-WindowsFeature Web-Server, Web-Ftp-Server, Web-Ftp-Service -IncludeManagementTools
Import-Module WebAdministration
New-WebFtpSite -Name "INF_FTP" -IPAddress 192.168.100.50 -Port 21 -PhysicalPath "C:\MOJE_FTP"
$s = "IIS:\Sites\INF_FTP"
Set-ItemProperty $s -Name ftpServer.security.ssl.controlChannelPolicy -Value 0
Set-ItemProperty $s -Name ftpServer.security.ssl.dataChannelPolicy -Value 0
Set-ItemProperty $s -Name ftpServer.security.authentication.anonymousAuthentication.enabled -Value $true
Set-ItemProperty $s -Name ftpServer.security.authentication.basicAuthentication.enabled -Value $true
Add-WebConfiguration "/system.ftpServer/security/authorization" -PSPath IIS:\ -Location "INF_FTP" -Value @{accessType="Allow";users="?";permissions="Read"}
Add-WebConfiguration "/system.ftpServer/security/authorization" -PSPath IIS:\ -Location "INF_FTP" -Value @{accessType="Allow";users="Administrator";permissions="Read,Write"}
Rename-Computer -NewName "SERWERX" -Restart
```

**Как проверить**
- `ipconfig` (LAN1 = 192.168.100.50), `hostname`, `Get-Printer`, на самом сервере `ftp 192.168.100.50` (логин `anonymous`).

**За что дают баллы**
- Имена LAN1/LAN2; LAN1 получает 192.168.100.50; LAN2 = 192.168.0.X/24; принтер 192.168.0.200; распечатка с номером стенда; имя SERWERX; роль IIS+FTP; сайт INF_FTP с путём, IP и портом 21; права (аноним — чтение, Administrator — чтение/запись); ping 192.168.0.200.

**Частые ошибки**
- Создавать сайт FTP до того, как LAN1 получил .50 — в списке IP адреса не будет.
- Не включить `Podstawowe` (Basic) — Administrator не войдёт.
- FileZilla зависает на листинге: перезапусти службу `Restart-Service ftpsvc` (чтобы брандмауэр подхватил FTP) или переключи FileZilla в активный режим.

## Задание 7. Linux-станция
**Что требуется**
- Проводное соединение `IP_PC`: `192.168.100.15/24`, шлюз `192.168.100.1`; Wi-Fi выключен.
- В терминале (со скриншотами на USB): каталог `LINUX_TERMINAL` на USB, группа `Technicy`, пользователь `Student1` с паролем `ZAQ!2wsx`, добавить в `Technicy`.
- FileZilla: подключиться к FTP как Administrator и показать содержимое.

**Как сделать**
На Ubuntu Desktop сетью управляет NetworkManager — имя соединения задаётся там:
```bash
ip a                                   # имя проводного интерфейса, напр. enp0s3
sudo nmcli con add type ethernet ifname enp0s3 con-name IP_PC \
  ipv4.method manual ipv4.addresses 192.168.100.15/24 ipv4.gateway 192.168.100.1
sudo nmcli con up IP_PC
nmcli radio wifi off                   # беспроводной интерфейс выключен
mkdir /media/$USER/Egzamin-x/LINUX_TERMINAL
sudo groupadd Technicy
sudo useradd -m -s /bin/bash Student1
sudo passwd Student1                   # ввести ZAQ!2wsx дважды
sudo usermod -aG Technicy Student1
id Student1
```
То же можно сделать графически: `Ustawienia → Sieć → Przewodowe → ⚙` (имя профиля `IP_PC`, вкладка `IPv4` → `Ręcznie`).
FileZilla: Serwer `192.168.100.50`, Użytkownik `Administrator`, Hasło `ZAQ!2wsx`, Port `21` → `Szybkie łączenie`.

**Как проверить**
```bash
nmcli con show           # активно IP_PC
ip a; ip r               # 192.168.100.15/24, default via 192.168.100.1
getent group Technicy    # Technicy:x:...:Student1
```

**За что дают баллы**
- Имя соединения IP_PC; адрес и шлюз; на скриншотах видны команды: каталог LINUX_TERMINAL, пользователь, группа, добавление в группу; FileZilla как Administrator на 192.168.100.50:21 показывает `EGZAMIN_INF02.txt`; ping роутера и сервера.

**Частые ошибки**
- Не сделать скриншот с видимыми командами (баллы за 5.3–5.6 только по скриншотам).
- `usermod -G` без `-a` — затирает другие группы.

## Задание 8. Проверка связи
**Что требуется**
- Станция → сервер и LAN роутера; сервер → принтер; на сервере показать адрес, полученный автоматически.

**Как сделать**
```bash
ping -c 4 192.168.100.1      # со станции: роутер
ping -c 4 192.168.100.50     # со станции: сервер
```
```powershell
ping 192.168.0.200           # с сервера: принтер
ipconfig                     # LAN1 = 192.168.100.50
```
Если сервер не отвечает на ping — включи правило `Udostępnianie plików i drukarek (żądanie echa — ICMPv4 — ruch przychodzący)`: `Enable-NetFirewallRule -Name FPS-ICMP4-ERQ-In`.

**За что дают баллы**
- Ответы на ping по всем трём направлениям; работающий FTP при экзаменаторе.
