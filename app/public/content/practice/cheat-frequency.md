# Что реально спрашивают на практике INF.02

Эта страница — статистика по **52 официальным листам SG** (сессии 2022-01 … 2026-06). Она нужна не для зубрёжки, а для выбора приоритета: что тренировать сначала, чтобы быстрее перейти порог 75%.

## Как читать проценты

`98%` не значит «получишь 98 баллов». Это значит: задание такого типа появляется примерно в 98% листов.

- **100%** — тренировать до автоматизма, встречается всегда.
- **75–99%** — почти обязательная база.
- **40–74%** — важно, встречается очень часто.
- **10–39%** — учить после базы.
- **меньше 10%** — редко; смотреть только когда основное уже уверенно.

Подсчёт полуавтоматический по текстам заданий и критериям `_zo`, погрешность возможна в 2–3 листа. Но для приоритетов этого достаточно.

## Как использовать таблицу в подготовке

### Шаг 1. Сначала гарантированная база

Тренируй до уровня «могу сделать без подсказки за 5–10 минут»:

1. LAN/DHCP на router.
2. IP/maska/brama на switch.
3. ping и firewall ICMP.
4. zrzuty ekranu с правильными именами.
5. identyfikacja sprzętu.
6. patchcord/Keystone/patch panel.

Почему: это почти всегда есть в листе и обычно даёт много простых критериев.

### Шаг 2. Потом связки, которые идут вместе

Не учи темы изолированно. CKE часто строит цепочки:

```
VLAN na przełączniku → porty → adres IP → ping
router LAN/DHCP → rezerwacja DHCP → klient dostaje adres → pokazanie ipconfig
AD DS → OU → użytkownik → folder → udział + NTFS → logowanie klientem
IIS → plik index.html → DNS A → otwarcie strony z klienta
```

Если умеешь только «создать пользователя», но не можешь проверить результат с клиента, часть баллов теряется.

### Шаг 3. Редкие темы — только после основных

`NIC Teaming`, `BitLocker`, `RDP`, `DHCP na Windows Server` встречаются редко. Не начинай подготовку с них. Для них достаточно знать, где находится настройка и какой минимальный результат нужен.

| Приоритет | Темы | Цель |

| 1 | router, switch, ping, zrzuty | сделать без ошибок на время |
| 2 | kabel, montaż, identyfikacja | не терять процедурные баллы |

## Главный вывод

На практике выигрывает не тот, кто знает самые редкие функции, а тот, кто **стабильно и быстро** делает частые задания и правильно документирует результат. Поэтому оценивай себя не по «я прочитал тему», а по «я сделал её на время и прошёл критерии».
