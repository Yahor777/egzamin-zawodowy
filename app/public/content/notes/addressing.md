# Адресация IPv4 и IPv6 (Adresacja IPv4 i IPv6)

## Основы IPv4
- Адрес IPv4 (adres IPv4) = **32 бита**, 4 октета (oktety) по 8 бит, запись десятичная с точками (zapis dziesiętny kropkowy).
- Адрес = часть сети (część sieciowa, network ID) + часть хоста (część hosta, host ID).
- Маска подсети (maska podsieci, subnet mask): единицы слева = сеть, нули = хост. Длина префикса (prefiks, /n) = **число начальных единиц в маске**.
- Маска должна быть непрерывной: `255.255.255.192` — верно, `255.250.255.0` — **ошибочна** (единицы не подряд).
- Адрес сети (adres sieci) — все биты хоста = 0. Широковещательный адрес (adres rozgłoszeniowy, broadcast) — все биты хоста = **1**.
- Число хостов (liczba hostów) = 2^(32−n) − 2 (минус адрес сети и broadcast).
- MAC-адрес (adres fizyczny/sprzętowy) — **48 бит**, уровень 2 OSI; первые **24 бита = OUI** (идентификатор производителя). Пример: `00:16:B9:00:1F:FE` и `00:16:B9:00:2F:FE` — один производитель.
- Максимальный размер датаграммы IPv4 вместе с заголовком — **64 kB** (65 535 B).
- Сокет (gniazdo, socket) = **IP-адрес + номер порта**.

## Классы адресов (klasy adresów) — классовая адресация
| Класс | Первые биты | 1-й октет | Маска по умолчанию | Хостов в сети |
|---|---|---|---|---|
| A | 0 | 0–127 (раб. 1–126) | /8 255.0.0.0 | 16 777 214 |
| B | 10 | 128–191 | /16 255.255.0.0 | 65 534 |
| C | 110 | 192–223 | /24 255.255.255.0 | 254 |
| D | 1110 | 224–239 | — multicast | — |
| E | 1111 | 240–255 | — экспериментальные | — |

- Класс A: **128 адресов сетей** (2^7; ответ банка), хостов 2^24−2.
- Двоичный адрес `00101000…` → начинается с 0 → **класс A**; `010…` → класс A; `10…` → класс B.
- Примеры из банка: 74.100.7.8 и 125.11.0.7 → A; 134.192.16.1 → B; 198.26.152.10, 220.191.0.3, 223.0.0.1 → C.
- CIDR (Classless Inter-Domain Routing) — **бесклассовая** адресация (/n произвольное). VLSM — маски разной длины в одной адресной области.

## Частные адреса (adresy prywatne, RFC 1918)
| Диапазон | Префикс | Класс |
|---|---|---|
| 10.0.0.0 – 10.255.255.255 | 10.0.0.0/8 | A |
| 172.16.0.0 – 172.31.255.255 | 172.16.0.0/12 | B |
| 192.168.0.0 – 192.168.255.255 | 192.168.0.0/16 | C |

- Ловушка: **172.168.0.16**, 172.32.x.x, 11.0.0.1, 194.204.152.34 — **публичные** (publiczne). 172.30.10.10 — частный.
- Частные адреса не маршрутизируются в Интернете → нужен NAT.

## Специальные адреса IPv4 (adresy specjalne)
| Адрес | Назначение |
|---|---|
| 0.0.0.0 | «этот хост»/маршрут по умолчанию (trasa domyślna 0.0.0.0/0) |
| 127.0.0.0/8, обычно **127.0.0.1** | петля (pętla zwrotna, loopback) = `localhost`, проверка стека TCP/IP |
| **169.254.0.0/16** (169.254.0.1–169.254.255.254) | **APIPA** — авто-адрес, если сервер DHCP не ответил |
| 224.0.0.0–239.255.255.255 | **multicast** (rozgłaszanie grupowe), класс D |
| 255.255.255.255 | ограниченный broadcast |
| 100.64.0.0/10 | CGNAT у провайдера |

Типы передачи: **unicast** (один-к-одному), **broadcast** (всем в сети), **multicast** (группе; получатели видны как один групповой получатель), **anycast** (ближайшему из группы, IPv6).

## Метод: адрес сети, broadcast, диапазон хостов
1. Найди «интересный» октет (где маска не 255 и не 0).
2. Шаг = 256 − маска в этом октете.
3. Адрес сети = наибольшее кратное шагу ≤ значения октета; октеты справа = 0.
4. Broadcast = адрес сети + шаг − 1 в этом октете; октеты справа = 255.
5. Первый хост = сеть + 1, последний хост = broadcast − 1.

**Пример 1:** 172.16.0.123/27 → шаг 32 → кратные: 0, 32, 64, **96**, 128 → сеть **172.16.0.96**, broadcast 172.16.0.127, хосты .97–.126.

**Пример 2:** 192.168.160.0/21 → 3-й октет, шаг 8 → 160…167 → broadcast **192.168.167.255**. Аналогично 192.168.0.0/20 → шаг 16 → broadcast **192.168.15.255**.

**Пример 3:** 88.89.90.91/6 → 1-й октет, шаг 4 → 88…91 → broadcast **91.255.255.255**.

**Пример 4:** 176.16.50.10/26 → шаг 64 → сеть .0, broadcast **176.16.50.63**, **62 хоста**.

**Пример 5:** принадлежит ли 10.160.255.255 сети 10.128.0.0/10? 2-й октет, шаг 64 → 128…191 → broadcast 10.191.255.255 → да, это **адрес хоста**.

**Пример 6:** 192.168.5.12/25, .50/25, .200/25, 192.**158**.5.250/25 → .0–.127 (две), .128–.255 (одна), плюс другая сеть 192.158 → **3 подсети**.

**Пример 7:** host 192.168.35.202/26 → шаг 64 → 192–255 → broadcast 192.168.35.255. Хост 192.168.160.224/28 → хосты .225–.238.

## Деление на N подсетей (podział na podsieci)
1. Заимствованных бит b: 2^b ≥ N (ровно N если N — степень двойки).
2. Новый префикс = старый + b.
3. Хостов в подсети = 2^(32 − новый) − 2.

| Задача из банка | Решение |
|---|---|
| 192.168.2.0/24 на 8 подсетей | b=3 → /27 → **255.255.255.224**, 30 хостов |
| 192.168.2.0/24 на 4 подсети | b=2 → /26 → **255.255.255.192** |
| 192.168.x.0/24 на 16 подсетей | b=4 → /28 → **255.255.255.240** |
| 10.0.0.0/16 на 4 | b=2 → /18 → **255.255.192.0** |
| 172.16.0.0/16 на 4 /18 | 172.16.**0**.0, .**64**.0, .**128**.0, .**192**.0 |
| 170.16.0.0/16 на 24 подсети | 2^5=32 ≥ 24 → **5 бит** |
| 10.0.10.0/24 на 16 | **4 бита** |
| /24 при маске .224 — сколько подсетей? | 2^3 = **8** |
| Нужно ровно 30 хостов из /24 | /27 → **8 подсетей** |
| Подсети по 510 хостов | 2^9−2=510 → /23 → **255.255.254.0** |
| 192.168.100.50/28 → 4 подсети | сеть .48/28 → /30: **.48, .52, .56, .60** |

Число хостов → маска: нужно h хостов → ищем минимальное k: 2^k − 2 ≥ h → префикс 32 − k.

## Суперсети и суммирование маршрутов (supernetting, trasa sumaryczna)
Метод: записать изменяющийся октет в двоичном виде, найти общие старшие биты.
- 10.10.168.0/23, 170.0/23, 172.0/23, 174.0/24 → диапазон 168–175.
- 168 = 1010**1**000, 175 = 1010**1**111 → общие первые 5 бит → 16 + 5 = **/21** → **10.10.168.0/21**.
- Проверка: блок /21 = шаг 8 в 3-м октете; 168 кратно 8 ✓.

## Двоичная запись адреса
- 192.168.1.12 = `11000000.10101000.00000001.00001100`.
- `10101010.00001111.10100000.11111100` = **170.15.160.252**.
- Веса бит: 128 64 32 16 8 4 2 1.

## Шлюз, маршрутизация, конфигурация хоста
- Брама по умолчанию (brama domyślna, default gateway) — IP интерфейса роутера **в той же подсети**, что и хост. Пакеты к чужой сети сначала идут на шлюз.
- Чтобы два хоста общались в LAN: одна сеть/маска, **разные IP** (одинаковые IP → конфликт адресов, konflikt adresów IP).
- Есть связь в LAN, нет с Интернетом → неверный/отсутствующий **адрес шлюза (роутера)**.
- Статическая маршрутизация (routing statyczny): сеть назначения + маска + next hop/интерфейс.
- Windows: `route ADD 192.168.10.0 MASK 255.255.255.0 192.168.10.1 5`, `route print`.
- Linux: `ip addr add 152.168.1.200/16 dev eth1`; `ifconfig eth0 172.16.31.1 netmask 255.255.0.0`; `route add default gw …`; `ifup eth0` — включить интерфейс.
- Коммутатору L2 IP-адрес назначают **для удалённого управления** (zdalny dostęp).

## DHCP и APIPA
- DHCP (Dynamic Host Configuration Protocol) раздаёт IP, маску, шлюз, DNS. Аренда (dzierżawa, lease), область (zakres, scope), исключения (wykluczenia).
- **Резервирование (zastrzeżenie, rezerwacja)** — постоянный IP по **MAC-адресу**.
- Нет ответа DHCP → Windows назначает **APIPA 169.254.x.x** (связь только в локальном сегменте).
- `ipconfig /release` — освободить; `/renew` — обновить аренду; `/all` — показать DNS, MAC, DHCP.

## NAT (Network Address Translation)
- Трансляция частных адресов LAN в один или несколько **публичных**; позволяет 18 хостам работать через 5 публичных адресов.
- PAT/NAPT (maskarada, overload) — много хостов за одним IP по разным портам.
- Статический NAT — 1:1 (например, публикация сервера), динамический — из пула.
- Признак NAT: локально 192.168.0.5, а сайт показывает 195.182.130.24.
- Cisco: `ip nat inside` / `ip nat outside` на интерфейсах.
- **NAT64** — трансляция между IPv6 и IPv4.

## IPv6
- **128 бит**, 8 блоков (hextetów) по **16 бит**, каждый — 4 шестнадцатеричные цифры, разделитель «:».
- Типичное деление: **64 бита префикс сети / 64 бита идентификатор интерфейса** (EUI-64 или случайный).
- Глобальный unicast: **глобальный префикс (48) → идентификатор подсети (16) → идентификатор интерфейса (64)**.
- В IPv6 **нет broadcast** — вместо него multicast. Автоконфигурация SLAAC.

| Тип | Префикс | Аналог IPv4 |
|---|---|---|
| Global unicast (globalny) | **2000::/3** (2xxx, 3xxx) | публичный |
| Link-local (lokalny łącza) | **fe80::/10** | APIPA 169.254 |
| Unique local (ULA) | fc00::/7 (практически fd00::/8) | частный |
| Multicast | **ff00::/8** | 224/4 |
| Loopback | **::1/128** | 127.0.0.1 |
| Unspecified | ::/128 | 0.0.0.0 |
| Документация | 2001:db8::/32 | — |
| IPv4-mapped | ::ffff:0:0/96 | — |

### Правила сокращения (skracanie zapisu)
1. Ведущие нули в блоке можно опустить: `0db8` → `db8`, `0000` → `0`.
2. **Один раз** последовательность нулевых блоков заменяется на `::`.
3. Двух `::` в адресе быть не может; нули внутри блока (`80ab`) убирать нельзя.

- `2020:0dc8:0000:0001:0000:0000:0000:0001` → **2020:dc8:0:1::1**.
- Развёртка: `2001:0:db8::1410:80ab` → 2001:0000:0db8:0000:0000:0000:1410:80ab (`::` = 3 блока, т.к. видно 5).
- Корректный: `1234:9ABC::123:DEF4`. Некорректны: два `::`, блок > 4 цифр, символы не 0–F.

## Частые ловушки на экзамене
- Хостов = 2^n − **2**: /22 → **1022**, /27 → 30, /29 → **6**, /24 → 254 (не 256).
- 172.168.x.x и 172.32.x.x — **публичные**; частные только 172.16–172.31.
- APIPA = **169.254.0.1–169.254.255.254**, а не 192.168 или 127.
- Broadcast — в части хоста **все единицы**; адрес сети — все нули.
- Link-local IPv6 = **FE80**, global = **2000::/3**, multicast = **ff00::/8**, loopback = **::1**.
- `::` используется **один раз** и заменяет только нулевые блоки.
- Маска «/n» = число **единиц** в маске; маска с разрывом (255.250.255.0) — ошибочна.
- Для деления на 24 подсети нужно 5 бит (2^4=16 < 24).
- Шлюз хоста должен быть в **его** подсети (K2 за интерфейсом G1 → шлюз = IP G1).
- MAC — 48 бит, уровень 2; IP — 32 бита, уровень 3.
