# Подсети IPv4: маска, адрес сети, broadcast, деление на podsieci

Эта страница нужна почти в каждом листе CKE: в задании адрес пишут как `192.168.16.0/24` или `100.100.100.8/28`, а в роутер/Windows надо ввести **десятичную маску** и понять, какие адреса можно использовать.

## 1. Сначала простыми словами

Типичная схема:

```
        WAN 100.100.100.9/28
              ┌────────┐
              │ RUTER  │ LAN 192.168.16.1/24
              └────────┘
                   │
        ┌──────────┴──────────┐
        │      PRZEŁĄCZNIK    │
        └──────────┴──────────┘
             │            │
      192.168.16.10  192.168.16.20
```

IPv4-адрес состоит из двух частей:

```
192.168.16.10 /24
└──── network ──┘└ host ┘
 192.168.16         .10
```

- **Префикс `/24`** — сколько первых бит адреса описывают сеть. `/24` = первые 24 бита.
- **Маска** — тот же префикс, записанный четырьмя числами: `/24` = `255.255.255.0`.
- **Адрес сети** — первый адрес подсети, у него host-биты равны нулю. Нельзя дать компьютеру.
- **Broadcast** — последний адрес подсети, у него host-биты равны единицам. Тоже нельзя дать компьютеру.
- **Host range** — адреса между network и broadcast; их можно давать устройствам.
- **Шлюз (brama domyślna)** — обычно адрес роутера в этой же подсети.
- **DHCP pool** — диапазон host-адресов для автоматической выдачи.
- **WAN/NAT** — внешний адрес и преобразование адресов на роутере. Для WAN часто дают очень маленькие сети `/28`, `/29`, `/30`.
- **VLAN** — логическое разделение сети; каждой VLAN обычно соответствует своя IP-подсеть.
- **Статический маршрут** — записывается именно как «адрес сети + маска + шлюз».
- **Management IP** — host-адрес устройства в правильной подсети.
- **SSID/WPA2** — к вычислениям IPv4 не относится, но Wi‑Fi клиенты тоже получают адрес из какой-то подсети.

## 2. Таблица масок, которую надо знать наизусть

| Префикс | Маска | Адресов всего | Host-адресов | Размер блока в последнем октете |
|---:|---|---:|---:|---:|
| /24 | `255.255.255.0` | 256 | 254 | 256 |
| /25 | `255.255.255.128` | 128 | 126 | 128 |
| /26 | `255.255.255.192` | 64 | 62 | 64 |
| /27 | `255.255.255.224` | 32 | 30 | 32 |
| /28 | `255.255.255.240` | 16 | 14 | 16 |
| /29 | `255.255.255.248` | 8 | 6 | 8 |
| /30 | `255.255.255.252` | 4 | 2 | 4 |

Формула:

```
всего адресов = 2^(32 − префикс)
host-адресов  = всего − 2        (кроме особых /31 и /32)
```

## 3. Метод за 5 шагов

Для любого адреса с префиксом делай одинаково:

1. **Переведи префикс в маску** по таблице или двоично.
2. Найди **размер блока**: `256 − последнее число маски` для масок /24–/30.
3. Раздели последний октет адреса на размер блока **без остатка** — получишь начало блока.
4. **Network** = начало блока. **Broadcast** = начало блока + размер − 1.
5. **Host range** = от network+1 до broadcast−1.

Для масок, где меняется не последний октет (`/16`, `/20` и т. п.), идея та же, но блок считается в соответствующем октете.

## 4. Пример 1 — маска из префикса: `192.168.16.35/26`

### Шаг 1. Покажем `/26` двоично

Префикс `/26` означает 26 единиц подряд:

```
11111111.11111111.11111111.11000000
└─8─────┘└─8─────┘└─8─────┘└2+6=8┘
```

Последний октет `11000000`:

```
128 + 64 = 192
```

Значит:

```
/26 = 255.255.255.192
```

### Шаг 2. Размер блока

```
256 − 192 = 64
```

В последнем октете сети идут блоками по 64:

```
0–63, 64–127, 128–191, 192–255
```

### Шаг 3. Где адрес `.35`

`35` находится в блоке `0–63`.

```
network:   192.168.16.0
broadcast: 192.168.16.63
host range: 192.168.16.1 – 192.168.16.62
```

Сам `192.168.16.35` — нормальный host-адрес. Его можно дать компьютеру или роутеру.

## 5. Пример 2 — network/broadcast/host range для WAN `100.100.100.9/28`

Это самый типичный случай на WAN.

### Шаг 1. Маска

```
/28:
11111111.11111111.11111111.11110000
```

Последний октет `11110000`:

```
128 + 64 + 32 + 16 = 240
```

```
/28 = 255.255.255.240
```

### Шаг 2. Размер блока

```
256 − 240 = 16
```

Блоки последнего октета:

```
0–15, 16–31, 32–47, 48–63, ...
```

### Шаг 3. Где адрес `.9`

`9` находится в блоке `0–15`.

```
network:   100.100.100.0
broadcast: 100.100.100.15
host range: 100.100.100.1 – 100.100.100.14
```

`100.100.100.9` — допустимый host. Если провайдер даёт шлюз `100.100.100.1`, всё согласуется: оба адреса в одной подсети.

В двоичном виде последний октет:

```
адрес .9:        00001001
маска /28:       11110000
network часть:   0000....  → .0
broadcast часть: 00001111  → .15
```

Проверка: нельзя назначить `100.100.100.0` или `100.100.100.15` интерфейсу WAN.

## 6. Пример 3 — разделить `192.168.20.0/24` на 4 подсети

Задача: нужны 4 сети для VLAN 10, 20, 30, 40.

### Шаг 1. Сколько бит добавить

Исходная сеть `/24` имеет 256 адресов. Делим на 4 части:

```
256 / 4 = 64 адреса в каждой
```

64 = `2^6`, значит на host-часть остаётся 6 бит. Всего бит 32:

```
32 − 6 = /26
```

То есть каждая новая сеть — `/26`, маска `255.255.255.192`.

Двоично это выглядит так: у `/24` было 24 единицы, мы добавляем ещё 2 бита на номер подсети:

```
/24: 11111111.11111111.11111111.00000000
/26: 11111111.11111111.11111111.11000000
                                    ^^
                              2 бита на 4 сети
```

`2^2 = 4` — как раз четыре варианта: `00`, `01`, `10`, `11`.

### Шаг 2. Выписать сети

Размер блока `64`:

| VLAN | Network | Host range | Broadcast | Маска |
|---|---|---|---|---|
| 10 | `192.168.20.0` | `.1–.62` | `.63` | `255.255.255.192` |
| 20 | `192.168.20.64` | `.65–.126` | `.127` | `255.255.255.192` |
| 30 | `192.168.20.128` | `.129–.190` | `.191` | `255.255.255.192` |
| 40 | `192.168.20.192` | `.193–.254` | `.255` | `255.255.255.192` |

Теперь можно назначить:

```
VLAN10 interface: 192.168.20.1/26, DHCP .10–.50
VLAN20 interface: 192.168.20.65/26, DHCP .70–.110
VLAN30 interface: 192.168.20.129/26
VLAN40 interface: 192.168.20.193/26
```

Главная проверка: адреса интерфейсов лежат в host range своих сетей и не пересекаются.

## 7. Как быстро проверять себя без калькулятора

| Вопрос | Быстрый ответ |
|---|---|
| `/26` — какая маска? | `255.255.255.192` |
| размер `/26`? | 64 |
| `/28` — какая маска? | `255.255.255.240` |
| размер `/28`? | 16 |
| `/30` — сколько host? | 2 |
| сеть `x.x.x.70/26`? | `.64` |
| broadcast `x.x.x.70/26`? | `.127` |
| можно ли `x.x.x.64/26` как host? | нет, это network |
| можно ли `x.x.x.127/26` как host? | нет, это broadcast |

## 8. Типичные ошибки и сообщения симулятора

Ошибки чаще всего всплывают при вводе адресов в роутере/свитче. Точные сообщения зависят от устройства:

| Сообщение симулятора | Что обычно не так | Как исправить |
|---|---|---|
| `Invalid subnet mask.` (SG108E), `Invalid subnet mask, please input another one.` (WR840N), `Invalid Subnet Mask.` (DrayTek), `The subnet mask is invalid.` (T2500G) | маска невозможна или префикс переведён неправильно | сверить с таблицей |
| `The IP address is not a valid host address for this subnet mask.` | вписан network или broadcast | возьми адрес из host range |
| `The destination network does not match the subnet mask (network address would be ...).` | в static route вписан host вместо network | введи адрес сети |
| `The destination must be a network address for this mask (host bits must be 0).` | то же в DrayTek | обнули host-биты |
| `The default gateway must be in the same subnet as the IP address.` | шлюз из другой подсети | пересчитай network у шлюза и интерфейса |
| `The DHCP pool must be in the interface subnet (...)` | пул не попадает в сеть VLAN | пересчитай пул |
| `Start IP Address is invalid or outside the LAN subnet.` | то же в DrayTek | старт пула должен быть host внутри LAN |
| `разные подсети` на диагностике стола | ПК и устройство в разных network | временно дай ПК адрес из сети устройства |

## 9. Мини-тренировка

Попробуй сам, потом сверь:

| Задание | network | broadcast | host range | маска |
|---|---|---|---|---|
| `10.0.0.70/26` | `10.0.0.64` | `10.0.0.127` | `10.0.0.65–10.0.0.126` | `255.255.255.192` |
| `172.16.5.35/27` | `172.16.5.32` | `172.16.5.63` | `172.16.5.33–172.16.5.62` | `255.255.255.224` |

## 10. Что проверяет экзаменатор

Экзаменатор не спрашивает «расскажи двоичную систему» в практическом листе. Он видит результат:

- в WAN вписана правильная десятичная маска;
- IP устройства не равен network/broadcast;
- шлюз находится в той же подсети;
- DHCP pool лежит внутри LAN и не содержит адрес роутера;
- статический маршрут начинается с адреса сети;
- подсети VLAN не пересекаются.

Если сомневаешься, напиши на черновике последний октет в двоичном виде и отдели биты маски вертикальной чертой. Это быстрее, чем гадать.
