# Учебный путь INF.02: шаг за шагом за 7 недель

> **Даты в этом файле и в `curriculum.json` (календарь 24.11.2026–14.01.2027, `scheduled_date`) — исходный проект зимней сессии.**
> Экзамен — летняя сессия 2027 (июнь). Приложение больше не читает даты календаря: порядок модулей, пререквизиты, `kind` и `est_minutes`
> берутся из JSON, а даты считает `app/src/path/plan.ts` на лету от сегодняшнего дня до дат экзамена из «Настроек»
> (по умолчанию письменный 2027-06-02, практический 2027-06-14; точные даты — по расписанию CKE).

Файл с маршрутом для приложения — [`curriculum.json`](curriculum.json): 14 модулей, 143 шага, календарь по дням с 24.11.2026 по 14.01.2027 и 12 пробелов (gaps) с техзаданием.
Как получены цифры: `analysis/` (`zo.py` разбирает критерии оценки, `classify.py` относит каждый критерий к навыку, `agg.py` считает частоты, `build.py` собирает и проверяет `curriculum.json`). Все ссылки на конспекты, разделы, дриллы, лабы, теги вопросов и группы команд `build.py` сверяет с репозиторием: если ссылка битая, сборка падает.

Ученик: русскоязычный, 3-й класс technik informatyk. Windows Server знает «кликами» и хочет понимать его, Linux-сервер и теория слабые. Хочет всё делать сам и подсматривать только при затруднении.
Сроки: письменная часть 7–13.01.2027 (40 вопросов, 60 мин, порог 50 %), практическая 15–19.01.2027 (150 мин + 10 мин на чтение, порог 75 %).

### Почему такой порядок

1. **Сначала экзамен глазами экзаменатора (m00).** Ученик, который знает, что каждый пункт — это отдельный балл T/N, а скриншот без папки на Egzamin-x даёт 0, сразу работает аккуратнее. Входной тест настраивает дальше объём квизов.
2. **Числа → IPv4 → Windows-сеть → роутер/свитч.** Каждый шаг опирается на предыдущий: маска /27 нужна для WAN роутера, статический адрес на ПК нужен, чтобы зайти на свитч, а MAC из `ipconfig /all` — для резервирования DHCP. Этот блок (сеть ОС + ping + роутер + свитч) даёт около 36 % баллов любого листа, и в нём уже есть 22 готовых дрилла.
3. **Теория вперемешку с практикой.** OSI, порты и Wi‑Fi стоят между дриллами роутера и свитча: так легче запомнить, и письменная часть набирается с первой недели, а не в последний момент.
4. **Кабели и железо — в неделю 2–3.** Физическую работу всё равно нужно отработать руками в школе (offline_task), к этому моменту ученик уже понимает, зачем ему патч-панель и тестер. Идентификация (87 % листов) встроена сюда же.
5. **Linux — с нуля и медленно (неделя 3), сервисы — позже (неделя 4).** Это слабое место ученика и тема №1 в письменной части. Сначала оболочка, файлы, права, пользователи, netplan и NetworkManager, потом контрольная лабораторная. Службы (DHCP, Samba, Apache, SSH), диски и скрипты идут только после этого.
6. **Windows-клиент перед Windows Server.** Учётки, политики, NTFS и общий доступ сначала разбираются локально, потом то же самое в домене. Сервер подаётся как «знание + пошаговая инструкция + квиз на порядок шагов + один прогон на настоящей VM со скриптом `check-winserver.ps1`», без многочасового кликанья.
7. **Смета и рекомендации — до полных листов.** 8 баллов за 15 минут, их нужно забрать.
8. **Последние 2,5 недели — полные листы.** 9 обязательных листов под таймером 150 минут и 3 запасных. Используются только самые новые листы (2025–26), с разборами в `practice/inf02-*.md`. Сетевая и Linux-часть проверяются лабораторной автоматически, серверная — на VM или «бумажным прогоном» с самооценкой по критериям zo. Каждый потерянный критерий завтра превращается в дрилл.
9. **Неделя письменной части — облегчённая.** Каждый будний день пробный письменный 40/60 и разбор ошибок, полные листы — только в праздник и на выходных. Последний день перед практикой — без нового материала.

## 3. Как показывать шаг в приложении

Каждый шаг в `curriculum.json` содержит `kind`, `objective_ru`, `refs[]` (с `route` и `section`), `prerequisites`, `exam_value` (доля листов и баллов по этому навыку или доля вопросов по теме) и `scheduled_date`.

**Экран «Сегодня»:** берёт `calendar.days[date]`. Показывает шаги дня, 15 минут «Учёбы» и буфер, если он есть. Непройденное переносится на следующий день, дни с полными листами закреплены и не сдвигаются.

**Страница шага** — всегда один и тот же порядок:
1. **Цель** — `objective_ru` одной фразой и «почему это важно»: из `exam_value`, например «есть в 87 % листов, ≈ 5 баллов».
2. **Коротко** (theory/demo) — 1 экран, собранный из `refs` типа note/howto/practice с `section`, полный текст открывается по ссылке. В конце 2–3 вопроса-самопроверки из банка по `topic`.
3. **Разобранный пример** (demo) — фрагмент реального листа и его критерии zo, решение показано шаг за шагом.
4. **Сделай сам** (drill/lab/quiz) — открывается `route` дрилла или лабораторной. Документация закрыта, пока ученик не нажмёт «Застрял».
5. **Проверка** — автопроверка дрилла или лабораторной (≥ 75 %), квиз (≥ 70 %), а для частей, которые симулятор не проверяет, — чек-лист T/N по критериям CKE.
6. **Если не получилось — лестница подсказок** (`hint_ladder`):
   1. **где искать**: ссылка на конкретный раздел нашей документации, без штрафа;
   2. **конкретная подсказка** к проваленной проверке («маска /27 = 255.255.255.224», «порт 1 должен быть untagged»), шаг засчитывается с коэффициентом ×0,75;
   3. **решение** (команды/клики) и объяснение «почему». Шаг не засчитывается как «сам», дрилл возвращается завтра с новым seed.
7. **После шага** — статус уходит в `inf02.practice.v1` (`progress.ts`). Интервалы такие: успех без подсказок — повтор через 3, 7 и 14 дней; провал или подсказка 3-го уровня — повтор завтра.

**Checkpoint** — дриллы из `review.drills_new_seed` с новым seed и квиз по `quiz_topics`, без доков. **Full-sheet** — лабораторная с таймером 150 минут (уже есть в `LabPage`) плюс разбор листа как ключ к серверной части. Итог — процент по всем критериям листа и список «завтра повторить».

## 4. Что резать, если не хватает времени

Режем снизу вверх, суммарно можно освободить до ~10 часов:
1. `optional_if_time`: m12-lab-3…8 и полные листы №10–12 (~8 ч).
2. `m03-extra` (проброс порта, port security — только в листах 2022–23), `m09-realvm` (повтор на настоящей VM).
3. `m08-rare` сократить до чтения шпаргалки: RRAS, квоты, NIC Teaming, RDP, бэкап вместе ≈ 1 % баллов.
4. `m11-english`, `m05-periph-print` — заменить квизом по ошибкам.
5. Пробные письменные №6–7 заменить режимом «Мои ошибки».

**Не резать ни при каких условиях:** m02 (сеть + ping), m03 (роутер/свитч/VLAN), m05-ident и кабели, m06 до netplan и пользователей, m08-adds/ou-users/shares/iis (как знание), m10 (смета), минимум 6 полных листов под таймером.
